01 / 문제 발견

대시보드가 왜 제출 보고서랑 다른 숫자를 보여주지?

CH2_분석보고서_6차.docx를 최종 점검하던 중, 대시보드(ch2/data.js)의 Model 1 지표가 보고서와 어긋난다는 걸 발견했습니다.

가장 극적인 사례는 완도군이었습니다. docx 보고서는 완도군을 구조적취약성지수 1.233으로 전국 1위로 명시하는데, 당시 대시보드는 0.228(순위 밖)로 표시하고 있었습니다.

02 / 원인 검증

원본 스크립트를 다시 실행해서 확인했습니다

Modeling/CH2/6차/script/model1_final.py — 사용자가 직접 찾아준 진짜 원본. 실행 결과가 docx와 소수점까지 일치했습니다.

원목업체_resid 방향은 이론(원목업체 많음 = 확산위험 높음)이 아니라, Y와의 실측 상관(r=-0.196, 음의 방향)에 맞춰 정렬한 것 — 다른 3개 도메인과 동일한 규칙. 6차 최종본은 이 규칙 그대로(direction=-1)이고, 대시보드만 이론적 방향(+1, "A안")으로 뒤집혀 있었습니다.
model1_final.py, 지자체대응역량·인위적확산 도메인 구성 로직

왜 하필 이 데이터가 섞여 들어왔나 — 타임라인

  • 6차 이전CH3 폴더(Modeling/CH3/2차_최종채택(A안))에서 "원목업체 부호를 이론대로 반전하면 어떨까"라는 A/B 실험 진행 — 이때는 아직 CH2 6차 모델이 존재하지 않았음
  • git 커밋 순서로 확인CH3 A안 script 커밋이 6차 모델링 script 커밋보다 먼저 — 구조적으로 6차 결정을 반영할 수 없는 시점
  • 병합 과정그 실험 폴더에 같이 있던 CH2 대시보드 사본이 최상위 ch2/ 폴더로 그대로 승격되며 A안 데이터가 "현재 대시보드"가 됨
  • 2026-07-31원본 model1_final.py 재발견 + 실행 → 이 문서의 검증 완료

04 / CH3 파급 효과

CH3 우선순위 산식이 CH2 위험지수 하나로만 결정됩니다

rebuild_ch3_priority.py 확인 결과 — priority_score = percentile_rank(위험지수). 배분갭은 산식에서 이미 제거됐고, 재발위험확률은 별도 조건일 뿐 순위엔 관여하지 않습니다.

즉 CH2 위험지수를 고치면 CH3 우선순위도 같은 공식으로 다시 계산돼야 앞뒤가 맞습니다. 실제로 재계산해보니:

135 / 222

10 / 15
TOP15 명단 교체 인원

지리적으로도 뚜렷합니다 — 빠지는 쪽은 강원·충청 내륙권, 들어오는 쪽은 경남·전남 남해안권에 몰립니다. 위험지수가 3개 도메인(노출도·기후위험도·인위적확산) 평균이라, 그중 하나의 부호를 뒤집으면 인위적확산 비중이 컸던 도시들이 구조적으로 극단 이동하는 겁니다.

✓
CH3 산식 자체는 손댈 필요 없음이미 검증된 원본 공식(위험지수 백분위)을 그대로 다시 돌리기만 하면 됩니다. CH2 때와 동일한 방식 — html·다른 로직 변경 없이 데이터만 교체.
