# CH4 맞춤형 방제설계 분석보고서 2차

작성 기준: CH2 7차 최종판, CH3 2차 B안 최종, CH4 v4 최종수정2 분석계획, Modeling/CH4/2차 구현 화면, ImPine_ver6 대시보드 반영 상태
작성일: 2026-07-31

## 0. 핵심 결론

CH4의 분석 방향은 유지해도 된다. CH4는 피해 발생을 새로 예측하는 모델이 아니라, CH3에서 선정된 우선지원 시군구를 대상으로 방제 규모, 예산 여력, 인력, 기간을 비교하는 실행 가능성 시뮬레이터다.

다만 최종 제출 전에는 세 가지를 반드시 관리해야 한다. 첫째, 결측값이 기본값으로 대체되는 경우 화면에서 경고해야 한다. 둘째, 재선충명시 예산이 0 또는 결측이라 산림병해충 포괄 예산으로 fallback되는 경우 KPI가 포괄 예산 기준 참고값임을 명확히 표시해야 한다. 셋째, CH4 생성 스크립트와 메타데이터에 남아 있는 CH2 6차 경로 표기를 CH2 7차 최종 기준으로 정리해야 한다.

ver6 대시보드 기준 CH3에서 CH4로 이동하는 URL 전달은 구현 완료되었다. 선택 지역 코드, 지역명, CH3 grade 기반 targetDays가 CH4 초기값으로 전달된다. 따라서 기존 v4 계획서에 남아 있던 미구현 및 코드 검증 필요 문장은 최종 보고서에서 ver6 기준 구현 완료 및 경로 검증 완료로 갱신해야 한다.

## 1. 분석 목적

CH4의 목적은 “어느 지역이 위험한가”를 다시 판단하는 것이 아니라, CH3에서 우선지원 대상으로 선정된 지역을 실제 행정 실행 조건으로 내려보는 것이다. 따라서 CH4는 다음 질문에 답한다.

- 이 지역에서 적용 가능한 방제 방식은 무엇인가?
- 공개 원자료 기준 피해목 수와 소나무류 면적 참고값을 넣었을 때 예상 비용은 어느 정도인가?
- 현재 예산 기준으로 감당 가능한가?
- 목표 작업일수 안에 필요한 인력은 몇 명인가?
- 어떤 입력값이 실측이고 어떤 입력값이 추정인가?

CH4의 핵심 방어문은 다음과 같다.

CH4는 확정 견적 산출기가 아니라, 검증 가능한 공개 원자료와 일부 근사 실측 인건비 참고치를 바탕으로 방제 규모, 예산 여력, 실행 가능성을 비교하는 의사결정 보조 도구다. 실제 집행 전에는 최신 지자체 예찰자료와 업체 견적으로 treeCount, treatment_area_ha, unitCost, dailyCapacityPerWorker를 교체해야 한다.

## 2. CH1-CH4 연결 구조

CH1은 피해 현황과 공개 원자료 기반 피해목 수를 제공한다. CH2는 구조적 취약성과 대응역량, 재선충명시 예산축을 제공한다. CH3는 우선지원 시군구, grade, 정책 유형, 긴급성 참고값을 제공한다. CH4는 이 결과를 받아 방제 방식별 비용, 인력, 기간을 계산한다.

이 연결 구조는 타당하다. 다만 CH4는 실행 물량과 비용을 다루기 때문에 CH2, CH3보다 데이터 시점과 결측에 훨씬 민감하다. 그래서 CH4에서는 입력값의 신뢰등급과 결측 여부를 화면과 보고서에 함께 표시해야 한다.

## 3. 입력 데이터와 기준

| 입력 | 사용 방식 | 주의점 |
|---|---|---|
| treeCount_reference | 2021.5~2022.4 단일 관리주기 피해고사목 수 | 2026년 현재 물량보다 과소추정 가능 |
| treeCount_scaled_current | 전국 피해 증가율 4.68배 단순 적용 참고값 | 지역별 실측값이 아니라 민감도 참고값 |
| pine_area_ha_reference | 소나무류 면적 참고값 | 실제 방제면적이 아님 |
| treatment_area_ha | 사용자가 확정해야 하는 실제 방제면적 | 기본값은 임시값 |
| budget_won_explicit | 재선충명시 대응예산 | CH2 공식 분석축 |
| budget_won_broad | 산림병해충 포괄 대응예산 | 재선충 전용 재원으로 해석 금지 |
| targetDays_suggested | CH3 grade 기반 내부 추정 | 공식 표준 소요일수 아님 |
| unitCost, dailyCapacity | 방식별 추정 단가와 작업량 | 확정 계약단가 아님 |

CH4의 피해목 수는 시군구 단위로 검증 가능한 공개 원자료의 최신 완결 주기인 2021.5~2022.4 기준값을 사용했다. 다만 2026년 현재 전국 피해 규모는 해당 기준 주기 대비 약 4.68배 증가했으므로, 본 계산값은 현재 실제 방제 물량을 과소추정할 수 있다. 실제 집행 전에는 최신 지자체 예찰자료 또는 산림청 확정자료로 교체해야 한다.

## 4. 분석 과정

1단계는 CH3 우선지원 지역을 CH4 대상 지역으로 전달하는 것이다. ver6 기준으로 CH3의 우선순위 표와 정책매칭 표에는 CH4로 보내기 링크가 들어가 있으며, URL 파라미터로 시군구 코드, 지역명, grade 기반 targetDays를 전달한다.

2단계는 CH1 기반 피해 규모를 연결하는 것이다. treeCount는 6개 관리주기 누적값을 쓰지 않고, 공개 원자료에서 검증 가능한 2021.5~2022.4 단일 관리주기 값을 사용한다. 기존 6주기 누적값은 CH4 실행 물량에 부적합하므로 참고용으로만 둔다.

3단계는 CH2 예산축을 연결하는 것이다. 기본 분석축은 재선충명시 예산이다. 다만 일부 지자체는 재선충 방제를 일반 산림병해충 방제 사업에 포괄 편성하므로, 재선충명시가 0 또는 결측인 경우 산림병해충 포괄 예산을 참고 상한 시나리오로 병기한다. 이때 포괄 예산은 재선충 전용 재원이 아니다.

4단계는 방제 방식별 비용과 인력·기간을 계산하는 것이다. 항공방제는 면적 ha 단위, 지상방제·수간주사·훈증·벌채는 피해목 본 단위, 드론방제는 소면적 ha 단위로 계산한다. 방식별 unitCost와 dailyCapacityPerWorker는 추정치이며, 인건비 20만원/인/일은 방제 전용 실측이 아니라 임업경영실태조사 기반 근사 실측 참고치다.

5단계는 결과를 “가능/불가”와 “최소비용 방식”으로 비교하는 것이다. 판정 조건은 예산 충족 여부, 최소 물량 조건, 주거지 인접 여부, 목표 작업일수 기준 필요 인력으로 구성된다. 이 결과는 최종 정책 추천이 아니라 사용자가 현장 조건을 조정하며 비교하는 실행 설계 참고값이다.

## 5. 구현 검증 결과

ver6 대시보드에는 CH3에서 CH4로 이동하는 링크가 반영되어 있다. CH4 화면도 ver6 내부 ch4 폴더에 배치되어 있으므로, 최종 제출은 ver6 패키지 기준으로 묶는 것이 안전하다. 과거 ver4 패키지의 CH3 링크는 Modeling/CH4/2차를 가리키는 구조가 남아 있어 zip 제출 시 깨질 수 있으므로 최종본으로 사용하면 안 된다.

현재 CH4 데이터는 222개 시군구를 포함한다. 데이터 품질 점검 결과 treeCount_reference 결측은 77개, pine_area_ha_reference 결측은 75개, ch1_data_available이 true인데 treeCount 또는 pine_area가 null인 지역은 31개였다. 따라서 ch1_data_available은 CH1 자료가 완전히 있음을 뜻하는 값이 아니라 지역 단위 연결 여부에 가까운 값으로 해석해야 한다.

예산 기준에서도 주의가 필요하다. 222개 중 97개는 재선충명시 예산이 0 또는 결측이어서 산림병해충 포괄 예산 fallback이 적용된다. 이 경우 KPI의 예산 대비 비율은 재선충 전용예산 기준이 아니라 포괄 예산 기준 참고값일 수 있으므로 화면과 발표에서 구분해야 한다.

## 6. 신뢰도 평가

| 항목 | 신뢰등급 | 해석 |
|---|---|---|
| 재선충명시 예산 | A/B | CH2 공식 분석축. 단, 예산서 분류 방식의 한계 존재 |
| 산림병해충 포괄 예산 | B | 보조 참고 상한. 재선충 전용 재원 아님 |
| treeCount_reference | B | 공개 원자료 기반 재계산. 2026 현재 대비 시간 격차 존재 |
| pine_area_ha_reference | B | 소나무류 면적 참고값. 피해면적 아님 |
| 인건비 20만원/인/일 | C | 임업경영실태조사 근사 실측. 방제 전용 조사 아님 |
| unitCost | D | 내부 추정. 업체 견적 필요 |
| dailyCapacityPerWorker | D | 내부 추정. 현장 조건에 따라 크게 변동 가능 |
| targetDays | D | CH3 grade 기반 내부 추정. 공식 기준 아님 |

신뢰성 측면에서 CH4는 “정답을 내는 계산기”가 아니라 “입력값을 교체할 수 있는 비교 프레임”으로 정당화해야 한다. 추정값이 많다는 점은 약점이지만, 이를 숨기지 않고 항목별 신뢰등급으로 공개하면 오히려 심사 대응력이 높아진다.

## 7. 남은 리스크와 수정 필요 사항

첫째, 결측값이 기본값으로 대체될 때 화면에 경고가 필요하다. 현재 일부 지역은 treeCount 또는 pine_area가 null이어도 50ha, 800본 같은 기본값으로 계산이 이어질 수 있다. 기본값 사용 자체는 시뮬레이터에서 허용 가능하지만, 화면에서 “결측 대체 기본값”이라고 명확히 표시해야 한다.

둘째, 예산 fallback의 표시가 더 필요하다. 상세표에는 재선충명시와 포괄 예산이 분리되어 있지만, KPI의 예산 대비 비율은 사용 중인 예산 기준을 더 명확히 보여줘야 한다. 특히 완도군처럼 재선충명시 예산이 0인 지역은 “포괄 예산 기준 참고값”이라는 라벨이 필요하다.

셋째, CH4 생성 스크립트와 메타데이터의 CH2 6차 경로 표기를 정리해야 한다. 실제 내용이 CH2 7차 최종과 같은 원자료라 하더라도, 최종 제출 문서와 산출물에서는 CH2 7차 최종판 기준으로 표기를 통일해야 한다.

넷째, CH4 분석계획서의 CH3와 CH4 연결이 아직 미구현이라는 문구는 ver6 기준으로 갱신해야 한다. 현재 ver6에서는 CH3에서 CH4로 가는 URL 전달과 CH4에서 CH3로 돌아가는 복귀 경로가 구현되어 있으므로, 최종 보고서에는 구현 완료로 적는 것이 맞다.

다섯째, CH4 화면의 데이터 신뢰도 표시를 “지역 단위”가 아니라 “항목 단위”로 바꾸는 것이 좋다. 같은 시군구라도 예산은 존재하지만 treeCount가 없을 수 있고, treeCount는 있으나 pine_area가 없을 수 있다. 따라서 최종 화면에서는 treeCount, pine_area, budget 각각에 대해 실측·재계산·포괄 fallback·기본값 대체 여부를 따로 표시하는 방식이 가장 안전하다.

여섯째, 보고서와 발표에서 CH4의 결과를 “추천 방제방식”이라고 강하게 말하기보다 “조건 내 최소비용 방식” 또는 “입력 조건 기준 가능 방식”으로 표현하는 것이 좋다. 현재 로직은 정책 효과를 검증한 것이 아니라 예산, 물량, 주거지 인접, 목표일수 조건을 만족하는 방식을 비교한 것이므로, 최종 의사결정은 현장조사와 업체 견적 이후에 이뤄진다고 설명해야 한다.

우선순위는 다음과 같다. 1순위는 결측 기본값 경고와 예산 fallback 라벨이다. 이는 화면을 켰을 때 바로 보이는 신뢰성 문제다. 2순위는 CH2 6차 경로·메타데이터 표기 정리다. 이는 제출 문서의 버전 일관성 문제다. 3순위는 CH4 계획서 문구 갱신이다. 이는 보고서 해석의 최신성 문제다. 4순위는 항목별 신뢰도 표시 고도화다. 이는 발표 방어력을 높이는 개선 사항이다.

## 8. 최종 해석

CH4 분석 과정은 방향과 큰 흐름이 타당하다. CH1의 현황 자료, CH2의 구조 진단과 예산축, CH3의 우선지원 결과를 받아 실행 조건으로 변환하는 구조는 CH1-CH4 파이프라인을 완결시킨다.

다만 CH4는 데이터 품질 표시가 핵심이다. 과거 기준 treeCount, 결측값 기본 대체, 포괄 예산 fallback, 단가·작업량 추정치를 명확히 드러내야 한다. 이 부분을 화면과 보고서에 정직하게 표시하면 CH4는 “부정확한 견적서”가 아니라 “현장자료로 교체 가능한 실행 설계 시뮬레이터”로 방어할 수 있다.

최종 심사 대응 문장은 다음과 같이 정리한다.

CH4는 공식 견적 산출기가 아니라, CH1-CH3에서 도출된 우선지원 지역을 대상으로 공개 원자료와 일부 근사 실측 인건비, 그리고 사용자가 교체 가능한 현장 입력값을 결합해 방제 방식별 비용·인력·기간을 비교하는 실행 가능성 시뮬레이터다. 현재 treeCount는 2021.5~2022.4 공개 원자료 기준이므로 2026년 현재 물량을 과소추정할 수 있으며, 실제 집행 전에는 최신 지자체 예찰자료와 업체 견적으로 입력값을 교체해야 한다.
