CH1-CH4 발표 전 리스크 정리

아래 항목은 심사위원 관점에서 공격받을 수 있는 부분을 두 갈래로 나눈 체크리스트입니다. 화면·데이터·링크가 오해를 만들면 반드시 수정하고, 방법론의 한계는 보고서와 발표 문구에 명시해 방어합니다.

높음: 질문 가능성 큼 중간: 설명 필요 낮음: 보조 주의 체크됨: 현재 반영 완료 미체크: 추가 반영 필요
핵심 방어문
CH4는 확정 견적이 아니라 공개자료 기반 실행 가능성 시뮬레이션입니다.

CH1은 현황, CH2는 구조 진단, CH3는 우선순위·정책매칭, CH4는 실행 조건 비교라는 역할을 끝까지 분리해야 합니다.

체크 기준: 완료 표시는 현재 ver6 대시보드 또는 기존 정리 파일에 반영된 항목입니다. 보고서 명시 항목은 문서 본문에 문장으로 들어가야 최종 완료로 볼 수 있습니다.

1. 무조건 바꿔야 되는 것

사용자가 화면에서 바로 오해할 수 있거나, 파일 간 버전이 충돌하거나, CH1-CH4 연결 흐름을 깨는 항목입니다.

12개 항목
높음 완료
CH3에서 CH4로 이동하는 링크CH3 우선순위 표와 정책매칭 표에서 CH4 화면으로 넘어가야 합니다.
ver6 CH3에 `CH4로 보내기` 링크와 `sgg`, `name`, `days` 전달을 반영했습니다.
높음 완료
CH4에서 CH3로 돌아가는 링크과거 ver4 경로로 돌아가면 최종 ver6 흐름이 깨집니다.
ver6 CH4의 복귀 링크를 `../ch3/ch3.html`로 수정했고 파일 존재도 확인했습니다.
높음 완료
CH2 버전 표기CH2 6차가 남아 있으면 최종 기준이 흔들립니다.
ver6 CH3의 표시 문구를 `CH2(7차 최종판)`으로 통일했습니다.
높음 완료
CH3 최종안 표기A안과 B안 기록이 섞이면 CH3의 최종 분석 방향이 불명확해집니다.
CH3 최종 보고서는 B안 기준으로 정리했고, 과거 비교요약 파일도 과거기록으로 분리했습니다.
높음 완료
CH4가 확정 견적처럼 보이는 표현비용·인력·일수 결과가 실제 계약금액처럼 보이면 심사위원에게 바로 공격받습니다.
ver6 CH4에 `확정 견적이 아닙니다`, `추정 포함`, `실행 가능성 비교` 문구가 들어가 있습니다.
높음 완료
CH4 treeCount 기준 시점2021.5~2022.4 기준값만 쓰면 2026 현재 물량을 과소추정할 수 있습니다.
ver6 CH4에 기준 treeCount와 2026 전국배율 참고값을 함께 표시하도록 반영했습니다.
높음 확인 필요
예산 기준의 우선순위산림병해충 포괄 예산을 주 기준처럼 쓰면 CH2 분석축과 충돌합니다.
상세표에는 재선충명시와 포괄 예산이 구분되어 있습니다. 다만 재선충명시가 0인 지역은 KPI의 예산 대비 비율이 포괄 예산 fallback 기준이 될 수 있으므로, 화면 또는 발표에서 `포괄 예산 기준 참고값`이라고 별도 설명해야 합니다.
높음 확인 필요
일부 지역 treeCount 결측의 조용한 기본값 대체완도군처럼 CH1 원자료가 없거나 강릉시처럼 플래그는 true인데 핵심 필드가 null인 지역은 기본값으로 대체될 수 있습니다.
현재 화면은 50ha, 800본 등 범용 기본값으로 계산을 이어갈 수 있습니다. 발표에서는 `결측 지역은 최신 지자체 자료 확인 대상`이라고 말하고, 가능하면 화면에 결측 경고를 추가해야 합니다.
높음 확인 필요
ch1_data_available 플래그와 실제 필드 결측 불일치강릉시처럼 ch1_data_available은 true지만 pine_area와 treeCount가 null인 사례가 있습니다.
결측 판정은 지역 단위 플래그만이 아니라 treeCount, pine_area 등 항목별 유효성으로 세분화해야 합니다. 고치기 전에는 `항목별 결측 확인 필요`라고 설명합니다.
높음 ver6 완료
CH4 연결 링크가 제출 패키지 밖을 가리킴과거 ver4 패키지의 CH3 링크는 `Modeling/CH4/2차`를 가리켜 zip 제출 시 깨질 수 있습니다.
ver6에서는 CH3 링크가 내부 `../ch4/ch4.html`을 가리키도록 수정했고, ver6 내부 ch4 폴더도 v4 구현본으로 교체했습니다. 최종 제출은 ver6 기준으로 묶어야 합니다.
높음 확인 필요
targetDays 산출 설명재발위험확률로 일수를 계산한 것처럼 보이면 CH3/CH4 논리가 꼬입니다.
화면과 보고서에서 `CH3 grade 기반 내부 기본값`으로 쓰고, 재발위험확률은 `urgentList 교차조건용`이라고 분리 표기해야 합니다.

2. 보고서에 명시하면 되는 것

데이터 한계나 모델 해석 한계입니다. 산출물을 바꿀 문제라기보다 심사위원 질문 전에 먼저 밝혀야 하는 항목입니다.

12개 항목
높음 보고서 필요
CH1 공식통계와 내부 원자료 시점 차이최신 전국 공식통계와 시군구 단위 내부 원자료는 시점과 완결성이 다릅니다.
CH1은 최신 피해 현황 파악, 내부 원자료는 시군구 패턴 분석용이라고 분리해 적습니다.
높음 보고서 필요
CH2 2016~2023 데이터 사용2026 현재 발생을 직접 예측하는 값처럼 말하면 위험합니다.
CH2는 장기 구조요인 기반 취약성 진단이며 실시간 예측이 아니라고 명시합니다.
높음 보고서 필요
Model 1/Model 2 해석 한계AUC와 발생확률을 절대적 예측성능처럼 과장하면 안 됩니다.
Model 1은 구조 취약성 지표, Model 2는 조기경보 성격의 재발 가능성 신호로 설명합니다.
높음 보고서 필요
예산 배분 R² 낮음최적 예산모형으로 주장하면 근거가 약합니다.
기존 평균 배분 대비 상대적 과소·과대 배분을 보여주는 진단 지표로 설명합니다.
높음 보고서 필요
CH3 RiskPct 의미종합 정책효과 점수처럼 보이면 과장입니다.
구조적 위험 백분위 기반 우선순위 점수라고 명시합니다.
중간 보고서 필요
recommended_policy 의미정책 효과 검증 결과가 아니라 취약 영역 기반 매칭입니다.
정책 추천이라는 말보다 정책 매칭 또는 대응 방향 제안이라고 표현합니다.
높음 보고서 필요
CH4 단가 추정 한계방제방식별 unitCost는 실제 계약 단가가 아닙니다.
공개자료 기반 비교용 추정 단가이며 지자체 계약 단가로 교체해야 한다고 씁니다.
중간 보고서 필요
인건비 20만원/인/일방제 전체 단가의 실측값으로 보이면 안 됩니다.
단가 전체 실측이 아니라 인건비 구성요소 참고치라고 명시합니다. 출처와 표본 정보가 화면에 직접 렌더링되지 않는 경우 발표에서 구두로 보완합니다.
높음 보고서 필요
pine_area와 treatment_area 구분소나무류 면적을 실제 방제면적으로 오해할 수 있습니다.
pine_area는 참고값, treatment_area는 사용자가 조정하는 실행 입력값이라고 씁니다.
높음 보고서 필요
현장 조건 미반영최신 예찰, 계약단가, 접근성, 주거지 거리, 장비 조건이 빠져 있습니다.
실제 집행 전 지자체 현장자료로 입력값을 교체해야 한다고 명시합니다.
높음 보고서 필요
CH4 보고서 부재CH1~CH3보다 문서 근거가 약해 보일 수 있습니다.
현재는 CH4 구현 화면과 v4 분석계획 기준이며, 최종 보고서는 추후 작성 예정이라고 솔직히 말합니다.
높음 보고서 필요
전체 흐름의 역할 구분현황, 구조 진단, 우선순위, 실행 설계를 같은 성격으로 말하면 논리가 약해집니다.
CH1 현황, CH2 구조 진단, CH3 정책 우선순위, CH4 실행 가능성 비교로 고정합니다.
CH1 방어문
CH1은 최신 전국 피해 규모를 파악하는 현황 파트이며, 시군구 내부 분석자료는 공개 원자료의 완결성을 기준으로 사용했습니다.
CH2-CH3 방어문
CH2와 CH3는 실시간 발생 예측이 아니라 구조적 취약성과 정책 우선순위를 진단하는 분석입니다.
CH4 방어문
CH4는 확정 견적이 아니라 공개자료와 사용자 입력을 결합한 실행 가능성 비교 시뮬레이션입니다.
작성 기준: CH2 7차 최종판, CH3 2차 B안 최종, CH4 v4 최종수정2 분석계획 및 CH4 2차 구현 화면, ver6 대시보드 적용 상태.
