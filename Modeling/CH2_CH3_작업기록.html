ch2/data.js 전면 재작성 + ch2.html 렌더링 로직 수정

구축

목업 생성 함수(mulberry32 시드 난수)를 걷어내고, 재구현 결과를 그대로 담은 정적 데이터로 교체. 존재하지 않던 강건성 지표(PCA 지수·기하평균 지수)는 삭제하고, 6차에 실제 있는 축A 임계값 민감도(§8)로 교체했다.

ch2/data.js — 전면 재작성, 222개 시군구 실측치 ch2/ch2.html — 섹션 01~04 렌더링 스크립트 전면 수정
바뀐 것
  • KPI 행 — 목업 난수 → 실측 AUC·between계수·배분갭 R²
  • 지수 안정성 검증표 — 가짜 LOO/몬테카를로 → 실측 축A 임계값 민감도(±0.3/±0.5/±0.7)
  • 모형 사양 비교표 — 가짜 3사양 비교 → 훈련 vs 홀드아웃 실측 계수표
  • 표본외 검증 차트 — RMSE(미산출 목업) → rolling-origin 실측 AUC
04

지도가 안 그려지는 문제 — 원인 파악 및 해결

문제해결

ch2.html이 ../ch1/korea_geo.js를 불러오려 했는데, 이 파일 자체가 프로젝트에 존재한 적이 없었다 — 지도는 처음부터 10개짜리 fallback 목록으로만 작동해왔다.

원인 — 실제 경계 GeoJSON은 ch1/data.js 안에 CH1_GEOJSON이라는 이름으로 이미 있었음(240개 일반구 분리 단위, sgg_cd 기준).
해결 순서
  • 사용자가 제공한 sigungu_code_crosswalk_2023.csv로 시도+시군구명 → 5자리 코드 매핑
  • 전북특별자치도/전라남도 등 도명 표기 차이 1건 보정 → 222개 전부 코드 매칭 성공
  • 다구시(수원시 등 11곳)는 세부구 코드 여러 개가 같은 시군구 값을 공유하도록 sgg_codes 배열 추가
  • ch2.html의 지도 참조를 KOREA_GEO → CH1_GEOJSON, 매칭 키를 이름 → sgg_cd로 전환
결과 — 취약성지수 지도·배분갭 지도 둘 다 실제 경계선으로 정상 렌더링 확인.
05

임상도 이원화(2019판 vs 2024판) 점검

검증

전국임상도 원본 2개년(2019_sgg_pine_forest.csv, 2024_sgg_pine_forest.csv)을 직접 대조해, 접경 6곳(양구·철원·고성·연천·파주·옹진)의 극단적 수치 변화가 최종보정4.csv에서 어떻게 처리됐는지 확인했다.

지역처리방식
양구군 · 철원군 · 강원 고성군보정(harmonize) — 8개년 값 통일, 보정_flag로 표시
강화군 · 인천 동구보정 — log_소나무림면적이 8개년 내내 고정값
연천군 · 파주시 · 옹진군미보정 — 대신 2016~2019 자료유효_flag=0으로 표본 자동 제외
결론 — 처리 방식은 지역마다 다르지만, 어느 쪽이든 두 판이 섞여 모델에 오염되어 들어가는 경우는 없음을 확인.

CH3 작업 범위 정리 — 모델링이 더 필요한가?

판단

"이거 모델링 따로 돌려야돼 아니면 대시보드만 만들면 돼?" 질문에 ch3.html 기존 틀을 분석해 답을 정리했다.

결론
  • 대시보드만으로 충분한 것 — 우선지원 순위(취약성지수−배분갭 수식), 정책 매칭(룰베이스), 산업기반 현황(설문 통계 정리)
  • 모델을 한 번 더 돌려야 하는 것 — 단기 경보 결합에 쓸 Model 2(조기경보모형)의 시군구별 현재 재발위험확률 — 이건 아직 아무도 실행한 적이 없었음
07

Model 2(조기경보모형) 재구현 — 7차

실행

t-1 확산이력(연속발생연수·집단발생여부·인접시군 피해밀도)을 frozen-gm 방식(훈련기간에서만 그룹평균 계산 후 고정 적용)으로 결합한 CRE 로지스틱 모형을 재구현했다.

지표재구현6차 원문판정
훈련 AUC0.9760.976일치
홀드아웃 AUC0.9110.9473.6%p 낮음
Rolling ≤2020→20210.9260.934근접
Rolling ≤2021→20220.9130.933근접
정성적 교차검증 — 6차 §9.3이 지목한 최우선 대응지역 7곳(고령군·포항시·성주군·대구동구·영주시·횡성군·제천시) 중 7곳 전부 이번 재구현 모형에서도 상위 24~37% 구간(재발위험확률 0.83 이상)으로 재확인됨 — 절대 수치는 다르지만 방향성은 일치.
시도한 대안 (기각)

신청서 초안의 "Model 1 전체" 표현을 근거로 통합지수 대신 4개 도메인 점수를 개별 투입하는 사양도 시도했으나, 개선폭이 미미하고 일부 계수 표준오차가 폭발(SE=5.8)해 불채택 — 원래의 단일지수 사양을 최종 채택.

ch3/data.js 작성 — CH2 + Model2(7차) + 산업조사 결합

구축

세 데이터 소스를 하나로 묶었다. 우선지원 순위는 CH2의 배분갭·유형화를 그대로 재사용하고, 긴급도는 7차 Model2 확률을, 실행가능성은 산업조사 수치를 결합했다.

핵심 설계 결정
  • 우세 도메인은 임의 4-도메인 argmax가 아니라 6차가 실제 쓰는 축A_위험요인유형(노출도/인위적확산-우세형/복합형)을 그대로 재사용
  • 취약성 상위 + 관할 시도 지원필요도 ≥3.2 또는 참여경험 ≤0.5% 인 곳은 "산업기반부족형"으로 재분류하는 4번째 트랙 추가
  • 단기경보결합 — 배분갭 "부족" 74개 시군구 × 7차 재발위험확률 ≥0.83 → 6개 최우선 대응지역 도출
