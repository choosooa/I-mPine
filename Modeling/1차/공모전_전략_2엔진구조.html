공모전 전략 — 2엔진 구조

구조적 취약성지수(설명용) + 조기경보모형(검증용) · 정리일 2026-07-29

전체 아키텍처 — 왜 모형을 하나로 합치면 안 되는가

지수에 과거이력·공간확산을 넣으면 AUC는 0.97까지 뛰지만, 그 순간 지수는 "구조적으로 왜 취약한가"가 아니라 "작년에 터진 곳이 올해도 터진다"는 걸 재확인하는 물건이 됩니다. 그러면 "취약성에 기여한 변수를 바탕으로 맞춤형 예산을 설계한다"는 프로젝트의 핵심 스토리 자체가 무너집니다 — 기여 변수가 전부 "작년 발생 여부"가 돼버리니 정책적으로 할 말이 없어집니다(예산을 더 준다고 작년 발생 이력이 바뀌진 않으니까요). 그래서 역할을 분리한 2엔진 구조를 추천합니다.

Model 1 — 구조적 취약성지수Model 2 — 조기경보모형
투입변수 노출도·기후·인위적확산·대응역량
(4도메인, 정책개입 가능한 변수만)		 Model 1 + 전년도 발생이력·인접확산
AUC 0.58~0.64 낮지만 정직 0.97 검증용
역할 "왜 취약한가" 설명 → 정책 설계 엔진 "이 프레임워크가 실제로 맞다"는 신뢰성 과시
산출물 시군구별 기여도 분해 발생확률 랭킹
이렇게 하면 심사 발표에서 "AUC가 왜 낮냐"는 질문에 "저희는 정책개입 가능한 구조변수만 썼고, 여기에 과거이력을 더하면 AUC 0.97까지 나온다는 것도 검증했습니다 — 다만 그건 '작년에 터진 곳이 또 터진다'는 당연한 결과라 정책설계엔 안 씁니다"라고 먼저 선수치는 답변이 가능해집니다. 이게 오히려 방법론적 성숙도를 어필하는 포인트가 됩니다.

Model 1이 실제로 하는 일 — 기여도 분해가 핵심

취약성지수 = 4개 도메인 점수의 가중합이므로, 시군구별로 어느 도메인이 점수를 밀어올렸는지 자동으로 분해됩니다.

지수_i = 0.25×노출도_i + 0.25×기후위험도_i + 0.25×인위적확산_i + 0.25×(-대응역량_i)

예를 들어 완도군의 지수가 높다면, 그게 "노출도 때문"인지 "대응역량이 낮아서"인지 도메인별 기여분을 그대로 계산할 수 있습니다(가중치×도메인점수). 이걸 시군구마다 스택바 차트로 보여주면:

기여 우세 도메인맞춤형 정책 방향
노출도·기후 기여가 큰 곳예찰·모니터링 예산(조기 발견 인프라)
인위적확산 기여가 큰 곳도로변/원목유통 관리 예산(이동경로 차단)
대응역량(역방향) 기여가 큰 곳기본 방제조직·인력 확충 예산
"얼마를 더 줄까"가 아니라 "어떤 종류의 지원이 필요한가"까지 구분해서 제안하는 게 됩니다. 이게 공모전에서 차별화 포인트입니다 — 대부분의 팀은 "취약한 곳에 예산 더"까지만 가고, 이 유형 매칭까지 가는 팀은 드뭅니다.

정책 제안까지 이어지는 흐름 (이미 다 만들어 놓은 것들)

  1. 취약성지수 산출(Model 1) → 시군구별 기여도 분해
  2. 배분갭 진단(이미 완료) → "위험 대비 예산이 R²=4%밖에 설명 안 됨" = 현재 배분이 위험을 거의 반영 못한다는 문제 제기
  3. 배분공식 시뮬레이션(이미 완료) → 완도군·의성군처럼 위험최상위인데 예산 0원인 곳을 구체적으로 지목, 재배분 시 어떤 변화가 생기는지 시뮬레이션
  4. 기여도 기반 지원 유형 매핑(아직 미작성) → 같은 "부족" 판정이라도 지자체마다 다른 처방 제안
  5. 조기경보모형(Model 2, AUC 0.97) → "이 프레임워크 전체가 실제로 검증됐다"는 신뢰도 보강용 부록

다음에 실제로 만들 것 (순서 추천)

  1. 시군구별 기여도 분해표 + 상위 취약지역 스택바 시각화 — 코드로 바로 만들 수 있습니다 (지수 계산식이 이미 있어서 분해가 자동)
  2. 기여도 패턴별 지자체 군집화(예: 노출도-우세형 / 역량-부족형 / 인위적확산-우세형) → 유형별 정책 템플릿
  3. 조기경보모형(Model 2)을 정식 섹션으로 보고서에 추가
