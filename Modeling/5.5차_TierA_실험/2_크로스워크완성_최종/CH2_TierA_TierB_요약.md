# CH2 도로소나무비율_500m: TierA vs TierB

## 1. 정의

### TierB (2023 고정)
- **값**: 2023년 기준 데이터를 모든 연도(2016~2023)에 복사
- **특징**: 시간불변 (시군구당 고유값 1개)
- **문제**: 2019→2020년 도로 소스 변경(ROAD_RANK 104등급 +91%)의 영향을 그대로 반영
  - 전국평균: 0.28(2019) → 0.34(2020) — 가짜 레벨시프트
  - 이는 실제 도로망 변화가 아니라 데이터 소스 변경 때문

### TierA (104제외 전체 재계산)
- **방법**: ROAD_RANK 104등급을 제외하고 2016~2023 각 해의 실제 도로 데이터로 버퍼 교차 면적 재계산
- **계산식**: `ratio = sum(road∩pine 교차면적) / sum(시군구 총 소나무면적)`
- **특징**: 연도별 실제 변동 반영 (시군구당 고유값 5~8개)
- **개선**: 소스 변경 레벨시프트 제거
  - 전국평균: 0.178~0.184 (연도별 실제 변동만 유지)
  - 분산도 절반 이상 감소 (0.296 → 0.128)

---

## 2. 왜 TierA를 써야 하는가

### 방법론적 이유
1. **정확성**: 2020년 도로 소스 변경 효과 제거
   - 2019→2020 급증이 현실적이지 않음 (도로는 1년에 +91% 증가하지 않음)
   - 역사적 도로 데이터로 재계산하면 매끄러운 추세 유지

2. **시간 변동 정보 보존**
   - TierB: 8년 동안 같은 값 → within 변동 0 (패널모형에서 손실)
   - TierA: 실제 연도별 변동 → 시계열 정보 활용 가능

3. **모형 견고성**
   - CRE/Mundlak 모형에서 time-varying 설명변수는 within 추정에 기여
   - TierB는 시간불변이라 between만 사용되므로 정보 낭비

### 정책적 이유
- 2023년만 갖고는 변화 추세를 못 봄
- 예측 모형이 과거 추세를 반영해야 신뢰도 높음

## 3. 결측 처리 (88행 채우기)

### 문제: 14개 통합시에서 112행 결측
- TierA 원시 데이터: 250개 세부코드 기준 (경기 고양시 4개 구별로 분리 등)
- 패널 구조: 229개 통합코드 기준 (고양시 1개로 통합)
- **매핑 실패**: 250→229 코드 변환 못해서 14곳 × 8년 = 112행 비어있음

### 해결: 면적가중 합산
1. **크로스워크 적용**: `CH2_crosswalk_250to229.csv` 사용
   ```
   예: 수원시
   - 250 세부코드: 41111, 41113, 41115, 41117 (수원의 4개 구)
   - 229 통합코드: 41110 (수원시)
   ```

2. **분자/분모 각각 합산**
   ```
   ratio_229 = sum(road_inter_ha_250) / sum(pine_ha_250)
   
   예: 수원시 2016
   = (41111의 교차면적 + 41113 + 41115 + 41117) / (41111의 소나무면적 + ... )
   ```
   - 비율 평균 금지 (가중평균이 아님)

3. **결과**
   - 88행 완전 채움 (11곳 × 8년, 모두 비결측)
   - 기존 결측 24행 유지 (동구·영등포구·중구 — 소나무 없는 곳)
   - 통합시 플래그 추가: `도로소나무비율_500m_TierA_통합시집계_flag` (1 = 구 합산)

| Between SD | 0.2956 | 0.1257 |

| 시군구간 Spearman | — | 0.513 |
| 2019→2020 변화 | 0.3463 → 0.3463 | 0.1827 → 0.1801 |

**해석**
- TierA가 실제 변동을 보임 (2020년 소스 변경도 극적이지 않게)
- Within 분산 > 0: 시계열 정보 추가
- Y 상관은 약하지만 TierA가 더 현실적
